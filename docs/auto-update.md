# GitHub 自动更新

服务每 15 分钟通过 `git ls-remote origin` 检查远端 `main` 的提交，不调用 WCL。同版本的新提交也会提示更新。只有管理员能在首页看到提示并点击“更新并重启”。版本号只在明确发布新版本时调整；版本标签采用 `v主版本.次版本.修订号`，例如 `v2.0.2`。

更新前必须满足：当前运行在 `main` 分支、Git 工作区没有未提交或未跟踪文件、没有排队或运行中的分析任务。服务只接受本地 `HEAD` 到远端 `main` 的快进更新。独立更新进程等待服务器退出，执行 `git fetch origin main` 和 `git merge --ff-only`，随后以原监听地址和端口重启 `server.py`。失败时也会重启原版本，并将原因写入 `data/app_update.log`。

发布更新时将代码提交并推送到 `main`。只有明确升级版本号时才创建新版本标签。运行旧版标签检查逻辑的安装，需要先手动快进到包含提交检查逻辑的版本；旧版服务不会自动发现同版本提交。此功能用于直接运行 `server.py` 的部署；由 systemd、容器或其他进程管理器托管时，应由该管理器负责重启，避免同时启动两个实例。
