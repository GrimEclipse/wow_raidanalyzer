# 分析配置与任务并发

## 原因

原 `WCL_MAX_JOB_THREADS` 默认值为 1，三个任务入口共用该容量限制。HTTP 线程和每个任务内部的 Pull 线程虽然存在，任务本身仍全局串行。高级单场页面以前也没有传递 `options`，因此即使 Boss 支持配置，单场流程仍使用全量默认值。

## 分析入口与开关

`/online` 整晚分析沿用所选 Boss 插件的配置结构，每次提交的选项应用于日志中的全部 Pull。新增分析项目使用各 Boss 插件声明的默认值，用户逐项开启或关闭复盘；切换 Boss 时分别保留本页填写值。高级单场页面也复用同一结构，支持布尔、数值、下拉、名单和分组字段。首页一键分析使用 Boss 默认配置，不提供额外的“轻量分析”勾选。通用前端不维护 Boss 机制名单。

| Boss | 可选分析组 |
| --- | --- |
| 1、2 号 | 保留既有配置，接入高级单场入口 |
| 3 号 | 可规避伤害；适应性感染与接圈 |
| 4 号 | 联合防御；箱子；可规避伤害；冰封烈焰漏断；霜火连射；元素爆炸；巨力重击；冲击波命中；蘑菇；旋壳方向 |
| 5 号 | 顶级掠食者技能处理；风暴承伤；囊肿放置与激活；侧风归因；场地推演 |
| 6 号 | 永恒毒液；贪婪盛宴消层；吃球；波浪命中 |
| 7 号 | 毒液搬运；撕裂；处斩；恐惧行军；具象；灵魂撕裂；幽暗炸弹；墓缚；永恒夜幕；凋零撕裂；冷酷处斩；场地推演；转阶段复盘 |
| 8 号 | 腐蚀浪潮与带蛋；被缚之怒；攫取毒牙；关键流程 |

多数 Boss 默认保持完整分析；7 号默认聚焦 P2 与连续回放。死亡与战复始终保留。报告只汇总已选项目，关闭项标明“本次未分析”，不能解读为零失误。

5 号关闭场地推演会跳过完整回放帧；保留囊肿判定时仍需风向采样。囊肿、侧风、场地推演都关闭时，不再请求 Resources、Boss 位置承伤或构建位置索引。7 号不再生成场地快照和机制工作台；连续回放可以单独关闭。“谁没被灵魂撕裂劈中”仍需要具象和玩家坐标，即使具象独立复盘关闭也保留该项必要的证据。全部位置项目关闭后跳过 Resources、NPC All 与具象坐标补采。关闭转阶段复盘后跳过对应治疗、Boss 承伤和药水光环。

4 号只选择冰封烈焰漏断时不读取伤害、光环、箱子追踪或坐标。元素爆炸归因需要冰火分配证据；即使霜火连射独立复盘关闭，也保留该项依赖的解析。箱子附带的蘑菇/冰火情景标签只使用本次选中项目的结果。

其他复盘项目仍可能共用基础施法、伤害和光环流，取消单个项目不一定减少相同数量的请求。耗时改善取决于日志时长、坐标分页、WCL 响应和缓存。

## 并发配置

| 配置 | 默认 | 范围 |
| --- | ---: | --- |
| `WCL_MAX_JOB_THREADS` | 4 | 全进程同时执行的分析任务 |
| `WCL_MAX_USER_JOB_THREADS` | 1 | 每个账号同时执行的任务 |
| `WCL_MAX_FIGHT_THREADS` | 4 | 一个任务内部的 Pull 并行 |
| `WCL_MAX_REQUEST_THREADS` | 6 | 全进程正在进行的 WCL 请求 |

环境变量优先于项目 `.env`；配置修改需要重启 `server.py`。旧部署如已显式设为 1，不会被新默认值覆盖。任务调度按等待顺序选择具备账号容量的任务；同账号的等待任务不占用全局执行槽位。失败时释放两层容量。

`4` 只是缺省值，没有固定的 4 任务上限。比如服务器允许同时运行 8 个任务时，在服务器项目根目录 `.env` 设置以下内容（或在服务启动环境中设置同名变量）：

```dotenv
WCL_MAX_JOB_THREADS=8
WCL_MAX_USER_JOB_THREADS=1
```

重启服务后生效，也可配置为 16 或更高的正整数。以上是配置示例，实际容量按服务器 CPU、内存和请求负载调整。`WCL_MAX_REQUEST_THREADS` 独立控制全进程 WCL 请求并发，提高任务数不会自动提高请求数。这些限制和队列属于单个 `server.py` 进程，多进程或多实例之间不共享。

## 排队状态

三个分析入口共用调度器。等待期间 `/api/jobs/<jobId>` 的 `status` 为 `queued`，`message` 显示运行数/容量、等待任务总数、入队顺序位置以及等待原因；页面既有状态区域直接展示该消息。队列增减、任务启动或释放容量时，等待任务会通过 SSE 推送变化，轮询状态接口和 SSE 心跳也携带结构化 `queue`：

```json
{
  "running": 8,
  "capacity": 8,
  "waiting": 3,
  "position": 2,
  "ahead": 1,
  "ownRunning": 0,
  "ownLimit": 1,
  "ownAhead": 0,
  "reason": "global_capacity"
}
```

`waiting` 包括当前任务；`position` 从 1 开始，`ahead` 是前方等待数，`ownAhead` 是当前账号排在前方的等待数。`reason` 为 `account_limit`（账号容量已满，优先显示）、`global_capacity`（全局容量已满）或 `queue_order`（等待前序调度）。运行后及终态 `queue` 为 `null`。位置表示入队顺序，不承诺严格执行顺序或预计时间：前序任务受账号限制时，其他账号可以先使用空位。接口只返回统计和当前任务位置，不返回其他账号或日志信息；权限仍仅限任务所属账号和管理员。

账号凭据、单场范围和进度回调使用上下文隔离，并传入 Pull 工作线程。结果继续放在账号目录，单场缓存键加入 WCL Client 范围及规范化后的选项。缓存通过唯一临时文件加原子替换写入，避免多个任务读取半份 JSON；缓存版本已更新，因此旧缓存不会误命中。宇宙之冕的请求统计也按分析上下文隔离。

## 验证

- 覆盖双账号任务同时进入分析、子线程的凭据/单场/进度隔离、同账号排队不阻挡其他账号、三种入口失败后的容量释放。
- 验证 3–8 号每个新增项目单独启用时能完成多 Pull 分析；关闭全部位置项后不调用位置取数与对应计算；仅选漏断跳过其他分析，单选灵魂撕裂保留具象证据并跳过制图。
- 验证不同选项的缓存分离、相同规范化配置命中相同缓存、不同 WCL Client 的缓存分离。
- 验证 8 账号同时进入任务、排队加入/前移/启动时的状态与 SSE 更新、账号等待原因、状态接口权限及三种入口失败后的队列清理。
- 浏览器从 `/online` 提交实际日志 `ZTcf3gMPmnBFVtvx`，只选择墓缚致死，成功分析 Fight 40、41、42；整夜统计仅保留该项，单场报告列明其余未分析项目。另验证 4、5、7 号默认选项及切换 Boss 后保留选择。

本地回归测试位于 `tests/test_analysis_job_concurrency.py`、`tests/test_job_queue_status.py`、`tests/test_optional_boss_analyses.py` 和既有 Boss/单场测试中；`tests/` 仍遵循仓库现有的本地开发目录忽略规则。

## 7号重点复盘（2026-10-23）

默认关闭剧毒洪流/毒液搬运、P1撕裂清场、处斩分摊与跑离、恐惧行军救人、P3详细复盘及转阶段统计；需要时仍可在单场配置中开启。默认保留具象、灵魂撕裂、炸弹误伤与盘魂者破盾、墓缚、永恒夜幕，以及连续回放。

- `fieldReplayEnabled`：连续战斗回放。开启后始终生成绿球/紫球的生成、搬运、落地与清除，各阶段头前的位置与方向，以及具象和炸弹的基础画面；关闭详细复盘子项不会删掉这些数据。
- `guillotineTelegraphEnabled`：回放处斩目标的6码预兆，持续至本轮最后一次命中；不依赖处斩详细复盘。
- `playerTimelineEnabled`：公共技能目录中实际成功施放的爆发、药水、饰品、嗜血与Boss机制对照。普通团队没有预定虚线或阿瓦隆战术归责。
- `guildTimelineEnabled`：仅对实际归属阿瓦隆、且未选择基础分析的史诗日志额外执行内置战术核对。公共配置不再提供爆发安排JSON导入。

回放事件与时间轴共享取证，不再重复读取整场Boss伤害、玩家施法和增益。回放只输出实际展示的玩家、Boss和盘魂者；位置查询复用每场索引。关闭时间轴后跳过其生成及专属检查。仍需坐标的机制即使关闭连续回放，也保留必要的判定取证。

基础画面证据单独存放在Boss局部的`replayMechanics`，详细复盘字段按各自开关输出；回放不会借由基础证据重新打开P1/P3页签或责任统计。处斩/冷酷处斩命中后的40码范围圈也独立保留，持续到实际脉冲事件（缺失时按6秒）；6码分摊预兆由`guillotineTelegraphEnabled`独立控制，到最后一次命中取消。旧报告仍按原有字段回放，新报告需重新生成；插件内容变更会使旧单场结果缓存失效。

10月17日第7把在全部详细复盘关闭时仍生成3次6码预兆与3次命中后范围圈。P3的1299266是开始信号，不作为第二次处斩；1299296为实际冷酷处斩伤害（WCL gameData确认），因此分摊预兆持续到真正伤害命中，而不是在1299267读条完成时提前消失。回放片段中可直接跳转“处斩预兆”“寡妇之吻范围”“死亡之拥范围”。

本地验证：10月17日第7把（8分04秒），一次无缓存真实WCL运行，从取证到JSON写出45.23秒，35次网络请求，接口逐请求记账112.34点。该时间不包含浏览器载入，也不是10分钟战斗的耗时承诺。8分钟缓存样本的相同机器CPU剖析中，全量旧流程约30.6秒，新流程约13.7秒；剖析器有额外开销，不应将其等同于真实网络端到端用时。

第二轮优化增加每个请求线程独立的HTTP连接池，继续遵守原有并发上限和重试策略；认证仅随本次请求传递，Cookie不在请求之间保留。炸弹轨迹复用时间索引与二分查询，炸弹伤害按目标预索引；盘魂者和灵魂绑定回放只排序相关事件。同一份258937条真实事件前后生成的完整单场报告字段一致。

同日后续强制绕过本地缓存的单次对照：关闭连接池30.63秒，启用连接池27.39秒，再加计算优化24.31秒（取证10.57秒、分析6.93秒）；三次均35次请求。本次WCL服务端逐请求计费约35–37点，与首轮112点不同，因此不能把首轮45.23秒到24.31秒的全部差异或额度下降归功于代码。网络状态和WCL服务端缓存会影响结果，上述均不含浏览器加载。计算优化的离线剖析从15.22秒降至12.39秒，剖析耗时也不等同于正常运行耗时。

随后修正了回放基础数据误受详细复盘开关影响的问题。因此24.31秒是修正前缺少P1/P3绿球和头前的版本，不能作为完整画面版本的端到端基准。修正后用同一份真实缓存事件验证：默认配置与关闭全部详细复盘的配置，均保留79段绿球/紫球地面区间、40段搬运记录、14次头前和34只具象，紧凑回放证据完全一致；默认配置单次本地分析计算7.67秒，全部详细复盘关闭时4.64秒，均不含取证与浏览器加载。

共享额度默认保留800点，适用于3600点容量。线上若已显式设置`WCL_RESERVE_POINTS=3000`，需要将环境变量改为800并重启`server.py`；代码默认值不会覆盖部署环境。
