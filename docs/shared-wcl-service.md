# Shared WCL service

`server.py` uses server-owned `WCL_CLIENT_ID` and `WCL_CLIENT_SECRET` for all users. User credential input, instructions and API mutations are retired (HTTP 410). Existing encrypted personal credentials are unused; no database or secret is included in a release.

Configure the new host with the existing `.env.example` settings and the owner's credentials in a private environment or `.env`. Set `WCL_RESERVE_POINTS=3000` (default). Runtime dependencies remain in `requirements.txt`; this change adds no package requirement. Use the server's real `rateLimitData` capacity rather than a hardcoded 18,000 limit. Moving machines does not itself prove a new quota.

Optional `WCL_SHARED_POOLS` is a private JSON environment value containing additional server-owned credentials. Each item has `clientId`, `clientSecret`, and optional `quotaGroup`. The primary and unspecified groups default to `shared`. Credentials sharing one quota group count once, using the most conservative observed remaining points. Assign different groups only when their independently reported quota is known to be separate. This is aggregation of authorized service credentials, not multiplication of capacity by token count.

`GET /api/wcl/status` returns only capacity, remaining points, reserve, reset time, availability and, for logged-in users, their own analysis usage. It never returns tokens, client identifiers or secrets. Pages display a small remaining-points progress bar. Pages refresh every 30 seconds; idle status queries reuse quota observations for up to five minutes. New-operation admission refreshes observations older than 30 seconds. Normal GraphQL responses update usage immediately without an additional request per event page. Hidden tabs stop polling; failed checks retry after 30 seconds and expired windows refresh immediately. A failed or unknown quota is shown as unavailable, never guessed as zero or full.

Ordinary users cannot start a new WCL operation below 3,000 remaining points. Only the `admin` role is exempt from that reserve and the analysis-count limit; `editor` is not. Nobody bypasses WCL's actual exhausted quota. Provider rate-limit responses temporarily close that quota group for new admissions. Already accepted analysis jobs continue rather than being stopped when the reserve is crossed.

Ordinary users have a rolling 60-minute allowance of 5 fights. Admission reserves one fight atomically before scheduling, then the generic selected-fight hook records each actual selected report/fight once per job. Re-running a fight is a new analysis and counts again. A cache-served single-fight request also occupies one allowance. An accepted whole-log job finishes every selected fight even when its total exceeds 5; the excess prevents subsequent tasks. Pending requests count toward admission to prevent rapid concurrent submissions from ignoring the allowance. The local SQLite ledger is `data/analysis_usage.db`, excluded from Git. Restarting does not erase the allowance. Keep this file when migrating the server if ongoing hourly usage must be preserved.

Run one application deployment against this ledger. Multiple hosts require a shared admission store and shared pool-status coordination before distributing workload; copying the SQLite file to independent hosts does not coordinate admission. Existing `WCL_MAX_JOB_THREADS`, `WCL_MAX_USER_JOB_THREADS`, fight concurrency and request concurrency still apply. Do not expose `.env`, `auth/`, `config.json`, WCL caches or the usage database through a web server.

Single-fight metadata records elapsed time, request count, cache hits, actual currentRequest.total WCL points and measurement coverage. Incomplete point measurements are null, with observed partial points stored separately. Cache-served results retain cold-analysis metrics separately from the current request cost. The 2026-10-13 measurement of the pre-tuning M7 public 9:07.2 kill used 40 requests, 41.43 points and 39.27 seconds cold; cached-result retrieval used one metadata request, 2 points and 3.74 seconds. These are individual samples, not fixed budgets. Five such cold analyses cost about 207 points; a 3,600-point pool with a 3,000-point reserve has only 600 shared ordinary-user points before admission closes.
