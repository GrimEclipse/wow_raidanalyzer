# 瓦什尼克与尼姆瑞莎机制复核

## 瓦什尼克波浪方向参考

依据 [NSRT 删除旋转提示前的 VashnikTheMalignant.lua](https://github.com/Reloe/NorthernSkyRaidTools/blob/afac04613349580b162c3515bd9fe2d23f469cbd/NorthernSkyRaidTools/EncounterAlerts/MidnightS2/VashnikTheMalignant.lua)，历史 WavesLine 使用 `MinimapCompassTexture:GetRotation()` 旋转水平与垂直参考线。它按预定分散、波浪时间显示或隐藏，也支持全场显示和 8 秒预览。这个实现提供世界方向参考，没有读取玩家点名、波浪坐标或实际锁定时刻。

本项目以日志实际记录的泡沫标记 1281913 应用、移除时间配对；Avalon ZFDWvrfqd6ygMKY2 / Fight 54 中 1281910 应用和移除同一时刻，不能用它替代持续标记。移除位置来自该玩家自身坐标，或带明确偏移值的近邻快照。方向参考显示为双轴虚线，不当作实测轨迹或射程。缺少起点或应用记录、死亡同时移除时不画参考线。波浪命中 1295798 仍独立陈列，不根据十字线归责。

仍需复核：真实波浪相对世界轴是否存在固定偏转、实际位置/方向锁定是在移除时还是提前发生。NSRT 的计时显示不能证明这些规则。DFT 尚未取得可核对的确切源码版本。

## 瓦什尼克木桩打法与光柱

按用户确认：任选五个不同光柱，无玩家固定分工。Boss 拉位不参与光柱距离计算。按痛饮 1284663 完成记录划分周期，泡沫 1281913 的应用批次划分点名；首波与痛饮后的第二批跳过，第一批以各人的正常移除时间作位置锚点。3 码为当前到位复核半径，并非声称技能有官方 3 码判定。死亡提前移除、未配对光环或坐标采样偏移超过 250ms 时不判未到位。

先读取本报告从开头到本战斗结束的 worldmarkerplaced/worldmarkerremoved（包含开战前），重建放置、移除状态。位置距离直接用 WCL 单位（坐标 / 100 = 码）。不同柱匹配采用至多 256 个光柱子集的动态规划，避免两个人靠近同柱被当作两人到位；多个最优解中可能被排除的人都列重复占位待复核，不任意选一个人归责。

**API 证据限制：** WCL 脚本 API 的 [Fight.worldMarkers](https://www.warcraftlogs.com/scripting-api-docs/warcraft/interfaces/RpgLogs.Fight.html) 存在，但 v2 GraphQL 的 ReportFight 不暴露该字段。2026-10-08 读取 Avalon ZFDWvrfqd6ygMKY2 / Fight 54 时，战斗内没有光柱事件；整份报告仅返回四条放置/移除事件，其中本房间只有菱形 (30760, 47522)。这证明“没有事件”不能当作“没有光柱”，也不能保证每份过本日志的公开 API 都带完整初始光柱。

该参考战斗单独附用户截图中六个未遮挡地面光柱的估算：菱形、十字、圆圈、三角、方块、月亮；菱形用 API 真坐标覆盖。星星、骷髅未补猜。截图位置以菱形为单点锚，像素比例暂取 0.0618 像素 / WCL 单位，因此距离只供待复核。其他团队或其他 Fight 不使用该布局。只有明确完整光柱快照（或八种柱全有真实记录）才依据缺席判未到位；五人分别到达五个已知真实柱可以确认到位，无需证明其他柱不存在。

场地显示采用用户第二张图片，以毒池中心、绿色分割线接点、入口侧分割线端点做近似对齐。原仿射映射产生了剪切，已改为等比例旋转/反射，使世界两轴在场地图上始终垂直且尺度相同。默认裁到红框内部，可切完整场地。地图变换不参与距离计算，不根据 Boss 坐标推测光柱。

## 垂直 X 推波与恶念图腾回放（2026-10-08 修正）

按用户确认，每名正常放波玩家生成固定垂直四向 X，有效宽度约 5 码（WCL 世界单位 500，总宽而非每侧 5 码）。以泡沫正常移除时刻和该玩家位置作为播放起点；死亡提前移除不产生模拟波。弧形亮边和渐隐拖尾沿四个方向前进，时间轴拖动、重播得到相同画面。当前动画速度 20 码/秒、射程 80 码是明确标注的模拟参数，尚非实测。波后观察窗口为 8 秒或下一批应用/战斗结束，以先发生者为准；不根据模拟交点自动归责。

图腾 NPC gameID 269430，恶念读条 1304459。使用一条带资源的 All 事件筛选 `source.id = 269430 or target.id = 269430`，不按 120 个实例分别请求。按 actor ID + instance 重建召唤、首次出现、开始读条、完成施法、死亡/消失以及本实例的坐标采样。没有死亡记录不推断已清除；不同实例不会共享坐标。固定图腾可用本实例后续坐标回看先前位置，悬停说明坐标采样时间；无坐标实例只出现在状态明细和计数中。

Fight 54 实测：120 个召唤实例、113 条死亡记录、121 次开始读条、1 次完成施法。带资源的 All 事件中仅 405:30 的完成施法附坐标 (26181, 42429)，相对时间 280.447 秒；ResourcesForEnemies 筛选返回 0 条。其余 119 个实例的状态有记录、位置尚未取得，不能声称开始读条事件均含坐标。第 2 批放波前 24 座，窗口内死亡 19 座、剩余 5 座；第 3 批这 5 座全记录死亡。死亡事件未给出波浪来源或击杀法术，不能单凭死亡时间确定哪名玩家清除了哪座。

光柱问题是不同接口的数据范围差异，而非只有一种柱受支持：GraphQL 放置/移除事件返回过菱形、星星和其他房间的月亮，但当前房间只有菱形记录。脚本 API 存在 `Fight.worldMarkers` 战斗数组，GraphQL ReportFight 无此字段；本次网站补充元数据请求返回 403 安全校验，浏览器读取报告也超时。未绕过校验，仍保留截图估算和证据不足提示。不能保证每份击杀日志的公开事件 API 都含完整初始柱。

新增图腾数据后的本机完整获取实测 18.517 秒 / 12 次网络请求；与旧版相比增加一条图腾筛选，保留流并发与证据缓存。后续代码调整重新计算 5.04 秒，9 次证据命中、3 次网络请求。网络延迟影响耗时，不承诺所有日志固定运行时间。Python 全套 554 passed / 1 skipped，包含新增公开脚本路由验证。JS 检查了四向推进、5 码总宽、死亡移除排除以及拖动重播确定性；浏览器核对了 24→5→0 的状态与推波光效。

前次光柱版本验证：`pytest tests -q` 550 passed / 1 skipped；工作台 JS 验证通过，浏览器已核对批次跳转及作战区/完整场地切换。独立数据流使用有上限的并发读取；不读取该 Boss 未使用且不带坐标的友方/敌方增益流。参考战强制完整重取从 28.7 秒 / 20 次网络查询降至 11.66 秒 / 11 次网络查询，专属机制数据（含位置、批次、判断）与优化前完全一致。更换感染合并窗口后的重新计算 4.28 秒，8 次证据缓存命中、3 次网络查询。这是本机参考战的实测，网络延迟和不同日志事件量会影响耗时。

## 尼姆瑞莎冰球固定逻辑

按用户确认：通常由坦克踩球，无需个人分工名单。集中放球和部分远程留中场输出鱼人均可，不根据分散程度判定个人责任。每轮陈列实际接触者、角色、最高层数、伤害记录与爆发伤害；光环证据单独存在时也保留接触者。伤害记录包含持续伤害，不表示球数或踩球次数。未知角色单独保留，不并入非坦克。
