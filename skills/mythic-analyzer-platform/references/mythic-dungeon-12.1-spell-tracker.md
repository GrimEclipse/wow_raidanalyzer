# 12.1 大秘境关键法术跟踪表

> 状态：持续补充。本文只保存已经确认的名称、Spell ID、目标规则和日志重建要求；没有实测证据的字段不猜测。

## 1. 输出合同

12.1 大秘境沿用当前 `/mythic-dungeon` 时间轴的输出方式：

- Pull 按实际发生时间排序，小怪实体保留实例编号；Boss 本体不显示“实例 1”，Boss 附属召唤物仍显示实例编号。
- 关键敌方技能优先记录 `begincast`；没有标准 Cast 的机制可由 Debuff、Buff、伤害或固定循环复原，但必须标注重建证据。
- 有明确目标的技能显示目标玩家；多目标技能显示完整目标集合。
- Boss 重复施法按机制轮次编号，例如“技能 1、技能 2、技能 3”。同步复制体施法只算一轮。
- 玩家时间轴记录成功 `cast`；状态型技能和物品若没有稳定 Cast，需要先确认其 WCL 事件链再决定如何复原。
- Boss 缺少死亡事件时，以成功 Boss Pull 的结束时间复原死亡时间和总存活时间。

#### 峡谷之灵固定循环

`1241067` 生效后，每 8 秒按以下顺序循环：

1. 光明之火
2. 凶残痛击
3. 光明坠落
4. 粉碎打击

实现时需要保存循环轮次和槽位，例如“循环 2 · 光明之火”。当前仍缺少“光明坠落”的 Spell ID。

光明之火在现有观察中可能以 `Unknown` 作为 Cast 来源。处理原则：

- 优先用 `1239825` 的三人 Debuff 集合确认真实发生时间和目标。
- 如果 Cast 来源确实缺失，只能在护光者鲁伊亚 Pull 内、且 `1241067` 已开始后，按固定循环补充 Boss 来源。
- 补充行必须标记为重建事件，并保存“峡谷之灵起点 + 8 秒循环 + Debuff 目标”证据。
- 若真实事件时间与理论 8 秒槽位偏差过大，不自动归并，留作异常证据。

### 数据边界

- WCL Zone：`56`，名称 `Mythic+ Season 2 (PTR)`。
- Partition：`1 / PTR`；Difficulty：`10 / Dungeon`。
- 本节所有样本均同时满足：报告 Zone 为 56、Fight 难度为 10、`kill=true`。

- 副本、Pull、Boss/小怪来源名称及来源 `gameID`。
- 技能中文名、Cast ID、Debuff/Buff/Damage ID。
- WCL 主事件类型：`begincast`、`cast`、`applydebuff`、`applybuff`、`damage` 或 `removebuff`。
- 是否有明确目标、目标数量、目标是否来自 Cast 本身。
- 是否需要实例编号、重复序号、固定循环或同步轮次合并。
- 用于验证的报告代码、Fight ID、Pull 时间和至少一轮原始事件。
- 无 Cast 的重建事件必须记录触发条件、结束条件、时间容差和异常处理方式。
